# AI 游戏开发规约（草案 v0.1）

> 状态：**草稿**——由每日雷达任务从 `research.md` 基线调研 + 本机工具实况沉淀，未经人工评审不生效；评审通过后再并入团队规约体系。
> 适用：2D 像素游戏小团队，Godot 4.7.2 为主引擎，CPU-only CI（Gitea Actions + MinIO）。
> 上游依据：`research.md`（全球调研基线）、团队规约（实验先行/人是第一责任人/REST优先/大资产不进Git）、`workflow-recommendations.md`（工具映射）。

## 0. 总则

1. **人是第一责任人**：AI 产出的代码、资产、文案、测试报告一律是草稿；进 `main`、进正式资产桶、进版本发布前必须人工评审。
2. **实验先行**：任何 AI 管线（生成、playtest、多代理）先在 `exp/*` 分支小样验证，设失败标准，成功才沉淀。
3. **契约式任务下发**：给 AI 的每个任务必须带——验收命令、可触碰文件白名单、禁止触碰清单、完成定义。禁止"你看着办"式开放任务。
4. **Token/预算纪律**：长会话分阶段提交、每阶段可跑可验；生成类 API 调用先小批试（≤20 张/次）确认风格再放量。
5. **大资产不进 Git**，正式批量产出走 CI，本地只做小样（团队规约 §0.3/0.4/0.5 沿用）。
6. **高内存/热约束**：CPU-only 机上编译 `nice -n 15 + --parallel ≤2`；批量处理先 `free -h` 估峰值（团队规约 §7 沿用）。

## 1. 立项与策划阶段

- **一页纸立项**：目标玩家、核心循环、垂直切片定义（2~4 周可玩）、AI 辅助边界（哪些交给 AI、哪些必须人工）。
- **Playbook 沉淀**：每个项目结束把"哪些 prompt/管线/资产配方有效"写回本仓库 `review/`，形成项目间复用的配方库。
- **AI 用途披露**：立项时即决定对外披露口径（Steam/Itch 政策要求，见 §6）。

## 2. 工程/代码阶段

- **角色分工**（按需召唤，不驻留）：
  - 方案设计 → 架构代理；实现 → 开发代理；完成后 → 评审代理过一遍再交人。
  - 性能问题**必须有 profiler 数据**才叫性能代理，禁止凭感觉优化。
- **MCP 引擎桥边界**（godot-ai）：
  - 允许：场景搭建、节点属性、脚本创建/补丁、tilemap/动画编辑、截图、读日志、跑测试——全部是**结构化参数**。
  - 禁止：`batch_execute` 塞任意脚本绕过参数白名单；headless CI 内调用 MCP（CI 走 `godot --headless` 原生命令）。
- **AI 不可一次性托管的模块**（必须人写或人逐段审）：存档/读档格式、加密、反作弊、支付、账号系统——出错代价不对称。
- **验收即命令**：每个 PR 的验收标准是可执行命令（`gdlint`、`godot --headless --script tests/xxx.gd`），不是"看起来没问题"。

## 3. 美术资产阶段

五段管线（详见 [workflow-recommendations.md §3.2](workflow-recommendations.md)）：

```
风格锁定（Aseprite 调色板 .gpl + 参考帧）
  → 云端小批生成（≤20 张/批，palette-conditioning 优先）
  → 本地标准化（magick 调色板量化 + 尺寸归一 → Aseprite 精修）
  → CI 批处理（图集打包 free-tex-packer-cli + 资产审计）
  → 溯源入库（prompt/工具/模型/日期/版权状态 → MinIO）
```

- **风格契约**：调色板文件 + 参考帧是一切生成的输入，没有风格契约不许开生成。
- **溯源与版权**：每批生成资产记录来源；训练数据不明的素材只进实验桶，沉淀进 `source-blend`/`source-aseprite` 前必须过版权审计。
- **命名规范**：`<域>_<对象>_<动作>_<帧序>` （如 `player_run_04.png`），审计脚本可校验。

## 4. 叙事 / 音频 / NPC 阶段

- **叙事**：世界观文档 + 角色卡先行（人写），AI 只做扩写/变体/本地化初翻；关键剧情节点人工逐条审。
- **对话系统**：配置驱动（Dialogue 资源/表格），AI 产出的对话进配置表走 PR 评审，不硬编码进场景。
- **NPC 架构**：LLM 只做"话术生成层"，行为决策用 FSM/行为树（LimboAI/Behave）——禁止把游戏逻辑裁决交给 LLM；无网/断 API 时 NPC 必须能降级为纯脚本行为。
- **音频**：生成类工具产出先小样评估；ffmpeg 负责后处理（归一、循环点裁剪、格式转换）；正式音效入库前人耳验收 + 版权审计（同 §3 溯源要求）。

## 5. 测试 / QA 阶段

- **分层**：单元（headless 脚本测试）→ 集成（场景冒烟）→ AI playtest（自动试玩 + 截图 + LLM 判读，见 workflow-recommendations §3.3）→ 人肉试玩（最终裁决）。
- **AI playtest 报告**：截图 + 判读结论进 MinIO `qa-report`（90 天生命周期）；报告只是线索，bug 修复前必须人工复现。
- **回归**：AI 改动一律带回归点清单；引擎/插件升级前跑全量冒烟。

## 6. 本地化 / 打包 / 发行阶段

- **本地化**：AI 初翻 → 术语表约束 → 人工校对；关键 UI 文案（按钮/教程）禁止纯机翻直出。
- **打包**：`godot --headless --export-release` 只在 CI 跑；产物进 MinIO `build-exp`/`build-artifact`，遵守桶生命周期。
- **AI 披露合规**（政策雷达持续更新）：Steam 需在商店页披露 AI 生成内容（预生成/运行时分开声明）；Itch 已有 AI 标签机制。**发行检查清单必须含 AI 披露项**，政策动态见每日雷达。
- **版本发布**：只走人工确认的流程（团队规约禁止行为沿用）。

## 7. 七大陷阱与对策（源自 research.md 基线，条目待每日雷达更新）

| # | 陷阱 | 对策 |
|---|---|---|
| 1 | 长会话上下文崩坏，后期产出质量骤降 | 分阶段提交，每阶段可运行可验收；上下文纪律（分块读/子代理隔离） |
| 2 | 开放式任务让 AI 自由发挥 | 契约式下发（§0.3），文件白名单 + 验收命令 |
| 3 | 生成资产风格漂移，拼进游戏像缝合怪 | 风格契约先行（§3），调色板量化兜底 |
| 4 | AI 生成的存档/加密模块有致命缺陷 | 拒绝清单（§2），此类模块人写人审 |
| 5 | 生成素材版权状态不明就上线 | 溯源入库（§3），披露合规（§6） |
| 6 | CI/生成 API 成本失控 | 小批试再放量（§0.4），CI 只跑增量 |
| 7 | 无人评审直接采纳 AI 结论 | 人是第一责任人（§0.1），每周 review 沉淀 |

## 8. 模型与工具选型

不在此复制选型表；以 `research.md` 选型总表为准，每日雷达发现的**新工具/新版本**追加到该表并在此处登记变更日期。选型原则：小任务用轻模型、架构/评审用重模型；本地 CPU-only 环境禁选依赖 GPU 的本地推理方案。
